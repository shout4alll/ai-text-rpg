# 🔔 알림 · 선톡 (앱 전용)

인물이 **내가 아무것도 안 하고 있을 때도 먼저** 안부·말·사진·영상을 보내는 기능.
알림은 서버가 아니라 **앱이 폰에 예약해 두는 알림(기기 예약 알림)** 이라 Firebase·서버 저장소가 필요 없다.
(웹 브라우저에서는 알림이 없다. 설정 화면에 안내만 나온다.)

## 동작

1. 앱이 **백그라운드로 가면** → 시간표대로 알림을 폰에 예약한다 (`lib/push/nudge.ts` → `scheduleNudges`).
2. 앱이 **다시 앞으로 오면** → 예약을 모두 취소한다 (지금 쓰는 중이니 알림이 필요 없다).
3. 알림에는 **누가 무엇을 보냈는지만** 보인다. 내용은 보이지 않는다.
   - `서지훈님이 메시지를 보냈습니다` / `…사진과 메시지를…` / `…영상과 메시지를…`
   - 잠금 화면에서는 내용을 숨기는 채널(`visibility: 0`).
4. 알림을 **누르거나, 나중에 앱·대화방을 열면** 인물이 실제로 먼저 말을 건다.
   - 서버 `/api/chat` 에 `kind: "return"` + `nudge: "message" | "photo" | "video"` 로 요청 → 말풍선 1~2개.
   - 사진·영상 선톡이면 서버가 **아직 안 보낸 앨범 항목**을 골라 같이 보낸다 (남은 게 없으면 말만).
   - 알림이 와 있는 대화방은 열 때 자동으로 전달된다. 48시간이 지난 알림은 버린다.

## 언제, 얼마나

| 항목 | 값 | 위치 |
| --- | --- | --- |
| 시간대 | **오전 9시 ~ 밤 10시 사이만**, 그 밖에는 **절대 안 보냄** (마지막은 21:50 이전) | `config/notifications.ts` `NOTIFY_WINDOW` |
| 횟수 | 하루 **3~4번** 랜덤 (시간대를 같은 길이로 나눠 칸마다 한 번 → 너무 붙지 않고 매일 다름, 최소 약 48분 간격) | `NOTIFY_PER_DAY` |
| 예약 범위 | 오늘 포함 3일 치. 그 뒤엔 앱을 다시 열어야 이어서 예약됨 (오래 안 오면 알림도 멈춤) | `NOTIFY_DAYS_AHEAD` |
| 앱을 닫은 직후 | 60분 안에는 안 보냄 | `NOTIFY_MIN_LEAD_MIN` |
| 누가 | 대화한 적 있는 인물 중 최근 대화한 순으로 자주, 같은 사람이 연달아 안 나옴. **삐져 있는 인물은 제외** | `lib/push/plan.ts` |
| 무엇을 | 메시지가 기본, 안 보낸 사진·영상이 있으면 약 30%가 사진·영상 | `lib/push/plan.ts` |

시간표 규칙은 순수 함수(`planNudges`)라서 기기 없이 시험할 수 있다 (2만 가지 시각으로 시험해 9시 이전·21:50 이후 0건 확인).

## 설정 화면

대화 목록 위쪽 **알림** 버튼, 또는 대화방 ⋯ 메뉴 **알림 설정**.

- **푸시 알림** 전체 on/off — 끄면 이미 예약된 알림도 바로 취소, 어떤 알림도 오지 않는다.
- **알림 종류** 토글: 메시지 선톡 / 사진·영상 선톡.
- 폰 알림 권한: 처음 **메시지를 보낼 때 한 번** 시스템 허용 창이 뜬다. 거절했다면 설정 화면에 폰 설정 안내가 나온다.

### 알림 종류를 늘리려면

`config/notifications.ts` 의 `NOTIFY_KINDS` 에 한 줄 추가하면 설정 화면 토글이 자동으로 생긴다.
새 종류를 보내는 코드에서는 `kindOn(settings, "새_종류_id")` 로 켜져 있는지 확인한다.
알림 id 는 종류별로 겹치지 않는 범위를 `NOTIFY_ID_BASE` 처럼 따로 잡는다 (선톡: 91000~91099).

## 저장 위치 (이 기기, localStorage)

| 키 | 내용 |
| --- | --- |
| `ai-rpg.notify` | 알림 설정 (전체·종류별·권한 질문 여부) |
| `ai-rpg.nudge.queue` | 도착했지만 아직 대화방에 전달하지 않은 선톡 |
| `ai-rpg.nudge.handled` | 전달 끝낸 선톡 키 (중복 방지) |

## 알아 둘 점

- 안드로이드는 배터리 절약(Doze) 때문에 예약 알림이 몇 분 늦게 울릴 수 있다 (정각 보장이 아닌 방식을 쓴다).
- 앱을 **삭제하거나 폰 설정에서 알림을 끄면** 오지 않는다 (서버 푸시가 아니므로).
- 서버 푸시(FCM/APNs)가 필요해지면: 기기 등록·대화 상태를 서버에 저장하는 구조가 먼저 필요하다 (지금 대화 기록은 폰 안에만 있다).
- 알림 아이콘: `android/app/src/main/res/drawable/ic_stat_chat.xml` (흰색 말풍선), 설정은 `capacitor.config.ts`.

## 답장 길이 (참고)

대화 답장 길이는 `lib/replyLength.ts` 가 매 턴 랜덤으로 정한다 (한마디 / 짧게 / 2개 / 연달아 3~4개 / 길게 / 신나서 4~5개).
유저가 짧게 보내면 짧은 쪽, 길게 털어놓으면 긴 쪽으로 가중치가 기운다. 비율은 같은 파일의 `MODES[].weight`.

## 알림이 안 올 때 (점검)
알림 설정 화면(앱)의 점검 칸에서 권한과 예약된 알림 수를 볼 수 있고, **테스트 알림 보내기**로 5초 뒤 시험 알림을 받을 수 있습니다.
1. 테스트 알림이 안 오면: 폰 설정 › 앱 › WitH › 알림 허용, 그리고 `npm install` → `npm run mobile:build` → APK 다시 설치(플러그인 포함 빌드인지 확인).
2. 테스트는 오는데 선톡이 안 오면: 앱을 홈으로 보낸 뒤 1시간 이후 ~ 오전 9시~밤 10시 사이로만 예약됩니다. 앱을 열어 둔 동안 예약 수는 0이 정상입니다.
