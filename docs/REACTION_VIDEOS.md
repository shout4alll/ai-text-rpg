# 리액션 영상 — 연출·무료/유료·캐릭터 확장 가이드

인물이 터치나 대화에 **영상으로 반응**하는 기능입니다. 영상 파일만 규칙대로 넣으면 코드를 고치지 않아도 바로 동작합니다.
현재 **서하린(character_a)** 에 영상 7개가 들어가 있습니다.

## 1. 서하린 영상 배치 (예시)

| 파일 (`public/avatar/personas/character_a/`) | 원본 | 쓰이는 때 |
| --- | --- | --- |
| `stage.jpg` | 부끄러움 영상 첫 장면 | 리액션 화면 기본 정지 이미지 |
| `clips/idle.mp4` | 부끄러움 영상 앞 1초를 왕복 재생 | 평소 (미세하게 움직이는 대기 화면) |
| `clips/shy.mp4` | 부끄러워하며 미소 | 부끄러움 (AI `shy`, 볼 터치) |
| `clips/laugh.mp4` | 웃으며 즐거워함 | 웃음·신남 (AI `laugh`/`excited`, 간지럼 터치) |
| `clips/love.mp4` | 사랑스럽게 바라봄 | 설렘 (AI `love`, 머리 쓰다듬기), 호감도 단계 상승, 오랜만의 재회, 화해 |
| `clips/pout.mp4` | 짜증 내며 토라짐 | 삐짐 (AI `pout`, 연타 터치) |
| `clips/turn_away.mp4` | 질려서 뒤돌아섬 | **등 돌림**: 상처 주는 말 또는 심한 연타 → 등 돌린 채 멈춤 |
| `clips/premium/kiss.mp4` | 손 키스 | **뽀뽀 (유료)**: 특별한 사이(호감도 75+)의 결정적 순간 |

- 원본은 1080×1920에 4~6초, 소리가 있는 영상이었습니다. 화면용으로 **720×1280, 무음, 빠른 시작 설정**으로 변환해서 용량을 개당 약 0.8~1.6MB로 줄였습니다(원본 2~4.5MB).
- 클립마다 첫 장면 구도가 조금씩 달라서, 전환할 때 0.28초 페이드를 줍니다. **다음 영상부터는 모든 클립을 같은 시작 이미지(stage.jpg)로 생성**하면 훨씬 매끄럽습니다.
- 영상 오른쪽 아래에 생성 도구의 워터마크(✦)가 보입니다. 상용 서비스 전에 워터마크 없는 플랜으로 다시 뽑는 걸 권장합니다.

## 2. 언제 영상이 나오나 — 연출 규칙

영상은 자주 나오면 금방 질립니다. 그래서 `lib/reactionDirector.ts`가 **"지금 영상을 틀 만한 순간인지"** 를 판단합니다. 아닌 순간에는 화면 움직임과 이모지만 보여 줍니다.

| 상황 | 결과 |
| --- | --- |
| AI 답장의 감정이 강함(웃음·부끄러움·설렘·삐짐 등) | 65% 확률로 영상. 영상 사이 12초 간격, 같은 영상은 45초 안에 반복하지 않음 |
| 마음 리액션(❤️ 등)에 말없이 표정으로 답할 때 | 85% 확률로 영상 |
| 호감도 **단계가 오를 때** | 쿨다운과 상관없이 **항상** 영상(설렘). 특별한 사이에 처음 들어서면 **뽀뽀(유료)** |
| 오랜만에 대화방에 돌아왔을 때 | 반가운 눈빛(설렘) 영상 |
| 상처 주는 말 (AI가 등 돌림을 고르거나 호감도 −3 이하) | **등 돌림** 영상 → 마지막 장면에서 멈춤 + "토라졌어요" 안내 |
| 등 돌린 상태에서 다정한 말 (호감도 +) | **화해 장면**: 다시 돌아보며 부끄러움·설렘 영상 |
| 첫 터치 | 바로 영상 (터치 영상 사이 7초, 같은 영상은 18초 간격) |
| 연타 중 | 앙탈 영상만, 나머지는 이모지 |
| 1.2초 간격 안에 9번 넘게 연타 | 등 돌림 → 20초 뒤 저절로 풀림 |
| 특별한 사이에서 머리 쓰다듬기 | 12% 확률로 뽀뽀 (유료, 10분에 한 번) |

빈도는 `DIRECTOR_TUNING`의 숫자만 바꾸면 조절됩니다. 등 돌림과 화해, 단계 상승 때의 뽀뽀처럼 **드물지만 확실한 보상 장면**이 다시 오게 만드는 장치입니다.

## 3. 무료 / 유료 영상

```
public/avatar/personas/<id>/clips/          ← 무료 (누구나)
public/avatar/personas/<id>/clips/premium/  ← 유료 (이용권 있을 때만)
```

- 유료 영상을 볼 수 없는 사용자에게는 대신 **무료 대체 영상**(뽀뽀 → 설렘)을 보여 줍니다. 그리고 10분에 한 번 "💋 특별한 리액션이 있어요 · PRO" 안내를 띄웁니다(구매 유도).
- 환경변수 `PREMIUM_ACCESS`: `open`이면 모두 공개(개발 기본값), `paid`면 잠금(배포 기본값).
  - 화면이 빌드 시점에 만들어지므로, 값을 바꾸면 **Redeploy**해야 반영됩니다.
- 어떤 리액션이든 유료로 만들 수 있습니다. 영상을 `premium/` 폴더로 옮기기만 하면 됩니다.
- **결제를 연동할 때 할 일:**
  1. `lib/entitlements.ts`에서 로그인 사용자별 구매 여부를 판단하도록 바꿉니다.
  2. `app/page.tsx`를 사용자별 렌더링으로 바꿉니다.
  3. 유료 영상을 `public/`이 아닌 비공개 저장소(예: Vercel Blob, S3)로 옮기고, 서명된 임시 URL로 내려줍니다. 지금은 주소를 알면 누구나 받을 수 있어서 진짜로 잠긴 상태가 아닙니다.

## 4. 다른 캐릭터에 영상 넣기 (코드 수정 없음)

1. `public/avatar/personas/<캐릭터id>/clips/`에 **리액션 id 이름**으로 mp4를 넣습니다. 영상이 없는 리액션은 움직임과 이모지로 자동 대체되므로, 일부만 있어도 됩니다.
2. 영상 첫 장면을 `stage.jpg`로 저장합니다(아래 명령). 영상과 같은 구도의 정지 화면이 생겨서 전환이 자연스럽습니다.
3. 유료 영상은 `clips/premium/`에 넣습니다.
4. 재배포합니다. 빌드할 때 폴더를 읽어 자동으로 인식합니다.

**권장 촬영 목록 (우선순위 순)**

| 순위 | 파일 | 장면 |
| --- | --- | --- |
| 1 | `idle` | 가만히 숨 쉬며 미소 (루프) |
| 1 | `shy` / `laugh` / `love` / `pout` | 부끄러움 / 웃음 / 사랑스러운 눈빛 / 토라짐 |
| 2 | `turn_away` | 질려서 등 돌림 (마지막 장면이 등 돌린 모습이어야 함) |
| 2 | `premium/kiss` | 손 키스 (유료) |
| 3 | `surprised`, `sad`, `touched`, `excited` | 놀람 / 속상함 / 감동 / 신남 |
| 3 | `touch_shy`, `touch_joy` … | 터치 전용 짧은 반응 1~2초 (없으면 위 영상을 씀) |
| 선택 | `talk` | 보이스톡 중 말하는 루프 |

**변환 명령 (원본 → 서비스용)**

```bash
# 리액션 클립: 720p, 무음, 빠른 시작
ffmpeg -i 원본.mp4 -an -vf "scale=720:-2,fps=24" -c:v libx264 -preset slow -crf 25 -pix_fmt yuv420p -g 12 -movflags +faststart shy.mp4

# idle: 원본 앞 1.1초를 느리게 왕복 (루프 이음새 없음)
ffmpeg -t 1.1 -i 원본.mp4 -an -filter_complex "[0:v]scale=720:-2,setpts=1.6*PTS,split[a][b];[b]reverse[r];[a][r]concat=n=2:v=1,fps=24[v]" -map "[v]" -c:v libx264 -crf 24 -pix_fmt yuv420p -movflags +faststart idle.mp4

# stage.jpg: 첫 장면
ffmpeg -i 원본.mp4 -frames:v 1 -vf scale=720:-2 -q:v 3 stage.jpg
```

`-g 12`는 키프레임 간격을 0.5초로 줄여서 처음 재생을 빠르게 하는 설정입니다.

## 5. 즉시 반응 처리

- 대화방을 열면 그 인물의 모든 영상을 **미리 받아 첫 장면에서 대기**시킵니다. 터치하면 다운로드 없이 바로 재생합니다(측정해 보니 화면 전환까지 1프레임 수준).
- 연출 판단은 브라우저 안에서 합니다. AI 호출이나 서버 왕복이 없습니다.
- 영상 수가 많아지면(인물당 15개 이상) 모바일 데이터가 부담될 수 있습니다. 그때는 `idle`과 상위 4개만 미리 받고 나머지는 필요할 때 받도록 바꾸면 됩니다(`VideoAvatar`의 `preload`).

## 6. 나중에 실시간 AI 영상으로 바꿀 때

구조를 세 단계로 나눠 두었습니다.

```
감정 판단 (AI 답장 / 터치)  →  연출 (reactionDirector)  →  재생기 (VideoAvatar)
```

실시간 영상 엔진이 나오면 **재생기만 바꾸면** 됩니다. 연출이 넘겨주는 `cue`(어떤 감정·움직임을 보여 줄지)를 미리 만든 영상 대신 실시간 생성 요청으로 넘기면 됩니다. 대화, 연출 규칙, 유료 구분은 그대로 씁니다.

- 현실적인 순서: 지금은 미리 만든 영상(무료·유료) → 실시간 생성이 빨라지면 유료 사용자부터 실시간 영상으로 → 비용이 내려가면 전체 적용.
- 실시간 엔진이 느리거나 실패하면 지금의 미리 만든 영상을 대체 수단으로 그대로 쓸 수 있습니다.
